# OnSeafog · 해무 너머의 부산

부산 해운대·수영구의 해무 조건을 지도와 시간별 기상자료로 탐색하는 INNOHACK 웹 프로젝트입니다. 선택 위치의 기상 조건을 점수로 확인하고, 관측자의 해발고도와 추정 해무층 높이를 비교할 수 있습니다.

**현재 모델은 설명 가능한 규칙 기반 모델입니다. 0–100점은 해무에 유리한 조건을 나타내며, 검증된 발생확률이나 정확도를 의미하지 않습니다.**

## 주요 기능

- **위치 선택**: Leaflet·OpenStreetMap 지도에서 임의 좌표를 클릭하거나 아이파크, 남천 엑슬루타워, 엘시티, 해운대·광안리 해수욕장을 선택합니다. 지도 이동과 확대·축소는 제한되어 있습니다.
- **시간별 탐색**: 2026년 7월의 31일 × 24시간 자료를 날짜 선택과 시간 재생으로 살펴보고, 점수 표시 기준을 조절합니다.
- **최신 예보 조회**: 선택 좌표의 JMA MSM 5km 기반 48시간 예보를 조회하고 5분마다 갱신합니다. 시간 기준은 한국 표준시(`Asia/Seoul`)입니다.
- **날짜 동기화**: 날짜 선택을 바꾸면 Follow the fog도 같은 날짜로 갱신됩니다. 선택한 시각이 해당 날짜에 있으면 유지하고, 없으면 첫 시각을 표시합니다.
- **관측 고도 비교**: 해발고도(0–2000m)를 입력해 해무 위 가능·해무 속·높이 미확정 판정을 확인합니다. 입력값은 좌표별로 현재 브라우저에 저장하며 초기화할 수 있습니다.
- **CSV 내보내기**: 선택 좌표·날짜의 기상자료, 조건 점수, 지점 판정을 저장합니다.
- **모바일 화면 및 재시도**: 모바일 레이아웃과 지도·기상자료 조회 실패 시 재시도를 지원합니다.

## 빠른 실행

**Node.js 22 이상**과 npm이 필요합니다. 아래 명령은 Windows PowerShell 기준이며, macOS/Linux에서는 `npm.cmd` 대신 `npm`을 사용합니다.

```powershell
git clone https://github.com/RenKRAP/INNOHACK_Project.git
cd INNOHACK_Project
npm.cmd ci
npm.cmd run dev
```

이미 저장소를 내려받았다면 저장소 루트에서 `npm.cmd ci`부터 실행합니다. 브라우저에서 <http://127.0.0.1:4173>을 열고, 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.

`dev`는 사이트를 빌드한 뒤 서버를 실행합니다. 파일을 수정했다면 종료 후 다시 실행해 빌드 결과를 갱신합니다. 포트를 바꾸려면 실행 전에 다음과 같이 설정합니다.

```powershell
$env:PORT = "4174"
npm.cmd run dev
```

사이트 실행에는 API 키나 데이터베이스 설정이 필요하지 않습니다. 기본 지점의 7월 자료는 저장소에 포함되어 있으며, 지도 타일·웹폰트·최신 예보·다른 좌표의 기상자료 조회에는 인터넷 연결이 필요합니다.

사이트 서버는 기본적으로 `127.0.0.1`에서 수신합니다. 배포 환경에서는 `HOST`와 `PORT` 환경변수로 수신 주소와 포트를 설정할 수 있습니다. 예를 들어 외부 요청을 받는 호스팅 환경에서는 `HOST=0.0.0.0`으로 설정하고, 빌드 명령은 `npm run build`, 시작 명령은 `npm start`를 사용합니다. 공개 주소와 HTTPS는 호스팅 서비스에서 설정해야 합니다.

## 실행 명령

저장소 루트에서 실행합니다.

| 명령 | 동작 |
|---|---|
| `npm.cmd run dev` | 빌드 후 로컬 사이트 서버 실행 |
| `npm.cmd run build` | 정적 파일·공유 모델·Leaflet을 `dist/`로 복사 |
| `npm.cmd start` | 이미 생성된 `dist/`를 로컬 서버에서 제공 |
| `npm.cmd test` | 모델, 지도 입력, 좌표별 자료 처리, 서버, 평가 도구 테스트 |
| `npm.cmd run data:refresh` | Open-Meteo에서 2026년 7월 기본 지점 자료를 다시 수집 |
| `npm.cmd run evaluate -- --labels data/observations.csv --threshold 65` | 별도로 준비한 실제 해무 관측 CSV와 모델 판정 비교 |

`data:refresh`는 네트워크를 사용하며 `data/july-2026.json`을 갱신합니다. `evaluate`의 관측 파일은 직접 준비해야 합니다.

## 사이트 API

사이트의 `local-server/`가 제공하는 읽기 전용 API입니다. 기본 주소는 `http://127.0.0.1:4173`입니다.

| 요청 | 응답 내용 |
|---|---|
| `GET /api/health` | 사이트 서버 상태 |
| `GET /api/weather` | 기본 지점의 최신 예보 (`mode=forecast` 기본값) |
| `GET /api/weather?mode=archive&lat=35.16&lon=129.17` | 지정 좌표의 2026년 7월 자료 |
| `GET /api/weather?mode=forecast&lat=35.16&lon=129.17` | 지정 좌표의 48시간 예보 (`refresh=1` 추가 시 캐시를 건너뛰고 조회) |

`lat`와 `lon`은 함께 전달합니다. 위도는 −90~90, 경도는 −180~180이며 소수점 5자리로 정규화합니다. 좌표를 생략한 최신 예보는 기본 지점을 사용합니다. 기상·해양 API 호출과 정규화는 서버에서 처리합니다.

외부 조회 결과는 서버 메모리에 최신 예보 5분, 과거 자료 24시간 동안 캐시하며 최대 32개를 보관합니다. 서버를 재시작하면 캐시는 초기화됩니다. 외부 자료를 가져오지 못하면 오류를 반환하고 화면에서 재시도할 수 있습니다.

## 데이터와 모델

### 입력 자료

[data/july-2026.json](data/july-2026.json)에는 2026년 7월 1일 00시부터 31일 23시까지 **744시간**의 자료가 포함되어 있습니다.

- 과거 기상: Open-Meteo GFS 과거 예보 아카이브
- 최신 기상: JMA MSM 5km의 기온·이슬점·상대습도·풍속·풍향, 기본 예보 모델의 가시거리·고도별 자료
- 해양: Open-Meteo Marine API의 해수면 온도
- 입력 항목: 기온, 상대습도, 이슬점, 풍향·풍속, 해수면 온도, 고도별 습도·지오포텐셜 고도
- 출처 기록: 수집시각, 조회 URL, 요청 좌표, 응답 격자 좌표를 JSON 메타데이터에 보관

저장 자료는 모델 기상자료이며 현장 실측 해무 기록이 아닙니다. 인접 좌표는 같은 기상 격자에 속해 점수가 같을 수 있습니다. 시간별 응답이 시간별 독립 실측을 뜻하지 않으며, 데이터 점검 결과는 [날씨 데이터 분석](docs/weather-data-audit.md)에 정리되어 있습니다.

### 판정 방식과 한계

[model/fog-model.js](model/fog-model.js)는 습도, 공기·바다 온도차, 이슬점 근접도, 풍향, 풍속을 조합해 조건 점수를 계산합니다. 기본 활성화 기준은 점수 65 이상, 기온이 해수면 온도보다 높음, 상대습도 80% 이상입니다. 이 기준은 통계적으로 최적화된 값이 아닙니다.

고도별 습도에서 지상과 연결된 습윤층 상단과 비교 범위를 추정합니다. 해무 조건이 활성화된 경우 관측 고도가 범위 상단보다 높으면 ‘해무 위 가능’, 그 이하면 ‘해무 속’으로 표시합니다. 입력이나 높이 자료가 부족하면 미확정으로 표시합니다. 비교 범위는 통계적 신뢰구간이 아니며 실제 시야를 보장하지 않습니다.

건물 높이는 관측자의 해발고도와 다릅니다. 건물 지점의 관측 고도는 직접 입력하며, 해수욕장 기본 고도 약 5m와 해안 참조점까지의 근사 거리는 정밀 측량값이 아닙니다. 지형·건물 차폐·시선 방향은 모델에 포함되지 않습니다.

현재 독립 관측 라벨이 없어 학습·확률 보정·정확도 검증은 완료되지 않았습니다. 과거 예보 아카이브와 해양 자료를 결합한 분석이므로 당시 발행시점의 예측 성능을 검증한 결과로 해석할 수 없습니다. 상세 수식과 미확정 처리 기준은 [모델 카드](docs/model-card.md)를 참고하세요.

### 실제 관측을 이용한 평가

[관측 템플릿](data/observations-template.csv)을 복사하여 `data/observations.csv`를 만들고 독립적으로 확인한 관측만 입력합니다. 헤더는 `time_kst,observed_fog`, 시간 형식은 `2026-07-01T00:00`, 관측값은 해무 있음 `1` / 없음 `0`입니다. 미관측 시간은 생략합니다. 저장소에는 실제 정답 라벨이 포함되어 있지 않습니다.

```powershell
npm.cmd run evaluate -- --labels data/observations.csv --threshold 65
```

평가 도구는 혼동행렬, 자료 커버리지, 정확도, 정밀도, 재현율, F1을 출력합니다. 관측이 없으면 평가를 거절하며, 기상자료가 없는 시간은 별도로 집계합니다. 임계값 조정과 최종 평가에는 서로 다른 기간을 사용해야 합니다.

## 폴더 구성

| 경로 | 역할 |
|---|---|
| `public/` | 한국어 웹 UI, 스타일, 지도·그래프·CSV 내보내기 |
| `model/` | 브라우저와 평가 도구가 공유하는 모델 및 기본 지점 |
| `local-server/` | **현재 사이트용** Node.js HTTP 서버와 기상자료 어댑터 |
| `Local_server/` | 기존 Express·Supabase PostgreSQL 연동 서버 |
| `data/` | 7월 기상자료 및 관측 CSV 템플릿 |
| `scripts/` | 빌드·기상자료 수집·관측 평가 스크립트 |
| `tests/` | Node.js 기본 테스트 러너 기반 테스트 |
| `docs/` | 요구사항 대응, 모델 카드, 기상자료 점검 문서 |
| `source/` | 기획 원본 문서와 평가 기준·API 참고 이미지 |
| `dist/` | 빌드 산출물 (Git 추적 제외) |

### 두 서버 폴더의 차이

`Local_server/`는 기존 `server/`의 이름을 변경해 보존한 별도 서버입니다. 현재 사이트는 `local-server/`로 동작하며 기존 데이터베이스 서버와 연결되어 있지 않습니다. 두 폴더는 이름과 실행 목적이 다릅니다.

기존 DB 서버가 필요한 경우에만 별도로 실행합니다.

```powershell
cd Local_server
npm.cmd ci
Copy-Item .env.example .env
# .env에 본인의 DATABASE_URL을 설정한 뒤 실행
npm.cmd run dev
```

기존 DB 서버의 기본 포트는 `3000`이며 `/health`는 DB 연결 상태, `/api/viewpoints`는 DB의 지점 목록을 제공합니다. 지점 조회에는 DB 연결과 [스키마](Local_server/schema.sql) 구성이 필요합니다. `.env`와 DB 비밀번호는 커밋하지 않습니다. 기존 배포 설정에서 `server/`를 참조한다면 `Local_server/` 경로로 수정해야 합니다.
