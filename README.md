# OnSeafog · 해무 너머의 부산

INNOHACK 요구사항을 바탕으로 만든 해운대 해무 탐색 웹사이트와 설명 가능한 예측 모델입니다. **외부 서버에 배포하지 않았습니다.** Node 서버는 로컬 주소 `127.0.0.1`에서만 실행됩니다.

## 실행

Node.js 22 이상이 필요합니다. Windows PowerShell에서는 다음 명령을 사용합니다.

```powershell
npm.cmd ci
npm.cmd run dev
```

브라우저에서 <http://127.0.0.1:4173>을 엽니다. 종료는 `Ctrl+C`입니다. 포트를 바꾸려면 실행 전에 `$env:PORT=4174`를 지정합니다. macOS/Linux에서는 `npm`을 사용합니다.

```powershell
npm.cmd test            # 모델·API 어댑터·서버·평가 로직 검증
npm.cmd run build      # dist 생성
npm.cmd start          # 기존 dist를 로컬에서 제공
npm.cmd run data:refresh # Open-Meteo에서 2026년 7월 자료 다시 수집
```

`data:refresh`는 저장된 자료를 갱신하므로 네트워크가 필요합니다. 기본 지점의 7월 분석은 포함된 744시간 JSON으로 동작합니다. 실제 OpenStreetMap 배경지도와 웹폰트, 최신 예보, 다른 좌표의 과거 자료 조회에는 인터넷이 필요합니다. 지도 타일 연결 실패 시 오류 안내와 재시도 버튼을 표시합니다.

## 구현 기능

- 해운대·수영구 실제 OpenStreetMap 고정 지도, 임의 좌표 클릭 분석과 5개 주요 지점 선택
- 최신 요구사항에 따라 지도 이동·확대·축소를 제한. 지도 내부 휠 클릭과 회전은 페이지 스크롤을 막고, 지도 밖에서는 브라우저 기본 스크롤 유지
- 아이파크·남천 엑슬루타워·엘시티와 해운대·광안리 해수욕장의 좌표별 시간 점수 및 기준 충족 시 해무 아이콘 표시
- 선택 위치의 관측 고도(해발 m) 입력·저장·초기화. 좌표별로 현재 브라우저에 저장하며 건물 높이와 관측 고도를 구분
- 2026년 7월 31일 × 24시간 탐색, 날짜 선택, 시간 재생, 점수 표시 기준 조절
- 좌표별 최신 3일 예보 조회와 5분 캐시, 7월 자료 조회와 24시간 캐시(최대 32개), 오류 안내 및 재시도
- 기온·해수면 온도·습도·이슬점·풍향·풍속 기반 0–100점 조건 모델
- 고도별 습도로 추정한 해무층 상단과 지점 고도의 비교: 해무 위 / 해무 아래 / 해무 속 / 미확정
- 선택 좌표·날짜의 기상자료·예측·지점 판정을 CSV로 내보내기
- 모바일 대응 화면과 모델 산정 방식 설명

## 예측 모델과 자료

모델은 [model/fog-model.js](model/fog-model.js)에 구현했습니다. 요구사항의 물리 조건을 수치화한 **규칙 기반 예측 기준선**입니다. 관측 라벨이 제공되지 않아 학습된 머신러닝 모델, 검증된 해무 발생확률 또는 정확도를 주장하지 않습니다. 점수 65는 초기 탐색 기준이며 통계적으로 최적화된 값이 아닙니다.

7월 자료는 실제 Open-Meteo GFS 과거 예보 아카이브와 해양 API에서 받은 모델 기상자료입니다. 현장 관측값이나 단일 발행시점의 예보 백테스트가 아닙니다. 자료의 조회 URL, 수집시각, 요청·실제 격자는 JSON에 기록했습니다. 자세한 수식, 해무층 추정과 한계는 [모델 카드](docs/model-card.md)를 참고하세요.

독립적인 실제 관측을 확보한 뒤 아래 형식의 CSV를 작성하여 평가할 수 있습니다. `observed_fog`는 사전에 정의한 관측 기준으로 확인한 경우에만 0/1로 입력합니다. 미관측 시간은 생략합니다.

```csv
time_kst,observed_fog
```

헤더만 있는 [관측 템플릿](data/observations-template.csv)을 제공합니다. 가상의 정답은 포함하지 않았습니다.

```powershell
npm.cmd run evaluate -- --labels data/observations.csv --threshold 65
```

도구는 혼동행렬, 자료 커버리지, 정확도, 정밀도, 재현율, F1을 출력합니다. 관측이 없으면 평가를 거절하고, 기상이 누락된 시간은 점수 계산에서 제외하여 따로 집계합니다. 임계값 조정 기간과 최종 평가 기간은 분리해야 합니다.

## 구성

| 위치 | 내용 |
|---|---|
| `public/` | 한국어 웹 UI, Leaflet 지도, SVG 그래프 |
| `model/` | 브라우저와 평가 도구에서 공유하는 예측 모델 |
| `local-server/` | 로컬 HTTP 서버, Open-Meteo 자료 정규화 |
| `server/` | 원격 저장소의 기존 Supabase 연동 서버 (변경 없이 보존) |
| `data/july-2026.json` | 출처 메타데이터를 포함한 744시간 자료 |
| `scripts/` | 빌드, 자료 수집, 관측 평가 도구 |
| `tests/` | Node 기본 테스트 러너로 실행하는 검증 |
| `docs/requirements.md` | 요구사항 대응 및 남은 검증 |

현재 구현에는 추가 환경변수나 API 키가 필요하지 않습니다. API는 `GET /api/health`, `GET /api/weather?mode=archive`, `GET /api/weather?mode=forecast`입니다. `&lat=35.16&lon=129.17`을 추가하면 해당 좌표로 조회합니다. 위도(-90~90)와 경도(-180~180)는 함께 전달하며 소수점 5자리로 정규화합니다. 기상·해양 API 호출은 서버에서 처리합니다. 인접 좌표는 같은 모델 격자를 사용해 점수가 같을 수 있습니다. 임의 좌표와 건물의 관측 고도는 입력 전까지 미확인으로 표시합니다. 해안 거리는 수동 지정한 해안 참조점까지의 근사 직선거리이며 정밀 해안선 GIS 측량값이 아닙니다. 창원 고층 관측·천리안 영상 등 추가 연동과 관측 검증은 남아 있습니다.
