**후속 변경:** 이 문서는 교체 전 GFS 경로와 저장된 7월 자료에 대한 분석 기록이다. 이후 기본 최신 예보 경로를 기상청 KIM-LDAPS 1km·시간별 48시간으로 변경했다. 아래 최신 예보 3일/GFS 설명은 교체 전 상태이며, 7월 자료의 수치·해상도·해시와 한계는 그대로다. KIM은 인증키 부재로 실제 응답 검증을 완료하지 못했다. 현재 설정·계약·한계는 [1km 예보 안내](1km-forecast.md)를 참고한다.

## 결론

저장된 2026년 7월 자료는 **744시간 전체가 연속적으로 존재하며, 모델 입력 13,392개에 결측이 없다.** 이는 데이터 완전성에 대한 결과다. 독립적인 관측 자료가 없어 기온·수온의 오차나 해무 예측 정확도는 아직 계산할 수 없다. 정확도가 0%라는 의미가 아니라 **미측정**이라는 의미다.

현재 자료는 해운대·수영 일대의 해무에 유리한 조건을 탐색하는 데 사용할 수 있다. 수십 km 규모 기상 격자와 성긴 고층 자료를 사용하므로 개별 건물·층의 실제 시야를 검증한 서비스로 해석하기는 어렵다. 지도에서 선택할 수 있는 좌표의 정밀도와 기상 자료의 공간 해상도는 서로 다르다.

## 2. 출처와 원자료 해상도

| 자료 | 코드의 선택 | 공식 문서상 해상도·주기 | 해석 |
|---|---|---|---|
| 지상 기상 | Open-Meteo `gfs_seamless` | GFS 전 지구 약 13km, 단기 시간 간격 1시간, 모델 갱신 6시간 | 건물 간 미세기후를 직접 관측한 자료가 아님 |
| 기압면 기상 | 같은 요청의 RH·고도 | GFS 기압면 약 25km | 얇은 해무층과 해안 지형을 세밀하게 구분하기 어려움 |
| 해수면 온도 | Marine API, `cell_selection=sea`, 제품 지정 없음 | 현재 문서의 Météo-France SST 제품은 약 8km·6시간 간격, 갱신 24시간 | 저장 응답에 정확한 제품 식별자가 없어 해당 파일이 이 제품을 사용했다고 확정할 수 없음 |

해상도와 갱신 주기는 [GFS 공식 문서](https://open-meteo.com/en/docs/gfs-api), SST 제품 사양과 자동 모델 선택은 [Marine 공식 문서](https://open-meteo.com/en/docs/marine-weather-api)를 확인했다. 시간별 SST 응답이 있다고 해서 시간별 독립 실측 수온이 있는 것은 아니다. 저장 파일만으로 제공자 측의 정확한 보간 방식도 확인할 수 없다. 작은 해안·항만·건물 주변 변화를 충분히 표현하기 어렵다는 평가는 이 공간 규모에 근거한 해석이다.

과거 기상은 관측소 실측이 아니라 Historical Forecast API의 **예보 아카이브**다. 공식 설명상 각 모델 실행의 초기 몇 시간을 이어 붙인 시간열이므로, 이 자료만으로 당시의 24시간·48시간 앞 예보 성능을 검증할 수 없다. 고정 리드타임 평가에는 개별 실행 자료가 필요하다. [Historical Forecast 공식 문서](https://open-meteo.com/en/docs/historical-forecast-api)

### 실제 선택된 격자

| 저장 자료 | 요청 좌표 | 응답 격자 좌표 | 두 좌표 간 거리 |
|---|---|---|---|
| 기상 | 35.1595, 129.1604 | 35.203384, 129.14062 | 약 5.20km |
| 해양 | 35.1200, 129.1600 | 35.12500, 129.12502 | 약 3.23km |

기상·해양 응답 격자 중심끼리는 약 **8.83km** 떨어져 있다. 거리는 지구 반지름 6,371km를 사용한 Haversine 근삿값이다. 이는 격자의 공간 대표성을 판단하기 위한 거리이며 GPS 위치 오차나 기온·수온 오차를 뜻하지 않는다. 기상 응답에는 좌표 메타데이터가 한 쌍만 저장되어 있어 지상·기압면 변수의 실제 원격자가 모두 같다고도 단정할 수 없다.

모든 기상 요청은 `elevation=0`을 사용한다. 제공자는 이 매개변수로 기온 등의 고도 보정을 제어한다. 따라서 현재 요청은 해수면 표면고도를 가정한다. 사용자 입력 해발고도는 날씨 요청이나 기온을 바꾸지 않고, 추정 해무 상단과의 비교에만 사용된다. [고도 매개변수 설명](https://open-meteo.com/en/docs/gfs-api)

가까운 두 클릭 위치가 같은 기상·해양 격자로 연결되면 점수도 같을 수 있다. 좌표 소수점 자릿수를 늘리는 것만으로 데이터 해상도가 높아지지는 않는다.

## 4. 해무 모델 정확도와 구분해야 할 사항

현재 모델은 `onseafog-rules-1.0` 규칙 기반 기준선이다. 습도 30점, 공기·바다 온도차 25점, 기온·이슬점 차 20점, 풍향 15점, 풍속 10점을 합산한다. 가중치와 기본 임계값 65는 실측 데이터로 학습·최적화한 값이 아니다. **점수 65는 해무 발생확률 65%가 아니다.**

기본 저장 좌표·기본 임계값으로 다시 계산한 결과:

| 항목 | 결과 |
|---|---|
| 점수 산정 가능 | 744/744시간 |
| 점수 범위 | 11~76 |
| 해무 조건 활성화 | **28시간 / 744시간 (3.76%)** |
| 활성화 중 상단 범위 산정 가능 | 27시간 |
| 나머지 활성화 시간 | 7월 15일 10시, 점수 68·RH 88%로 상단 추정의 RH 90% 기준 미충족 |
| 활성화된 27시간의 상단 비교 범위 폭 | **286~599m**, 평균 469.48m |

28시간은 관측된 해무 발생 횟수나 정확도가 아니다. 이전에 별도 좌표로 조회한 해운대해수욕장 사례의 시간 수와도 구분해야 한다.

상단은 지상과 연결된 RH 90% 이상의 층에서 첫 RH 90% 경계를 보간한다. 비교 범위는 아래 기압면 고도에서 50m를 빼고 위 기압면 고도에 50m를 더하는 규칙으로 만든다. **통계적 신뢰구간이나 전체 예측 오차 범위가 아니다.** 습윤층이 실제 가시적인 해무인지도 시정·응결량 등의 독립 자료로 확인하지 않았다.

현재 ‘해무 속’은 관측자 고도가 상단 비교 범위 이하인 경우를 통합한 표시다. 범위 내부의 불확실한 경우도 포함한다. 따라서 ‘해무 속’과 ‘해무 위 가능’은 조건부 모델 판단이며, 건물의 특정 층에서 해무가 보인다는 관측 보증이 아니다.

`data/observations-template.csv`에는 헤더만 있으며 **독립 해무 라벨은 0개**다. 현재는 기온·수온 MAE/RMSE, 해무 precision/recall/F1, 상단 높이 오차를 계산할 정답 자료가 없다. `scripts/evaluate.mjs`는 라벨이 확보되면 발생 판정의 혼동행렬·coverage·accuracy·precision·recall·F1을 계산하지만 기상 변수나 상단 높이의 오차 평가는 구현하지 않는다.

## 5. 검증 우선순위

1. **날씨 입력부터 검증:** 시간·위치·고도와 품질관리 조건이 확인된 관측소 기온·습도·바람, 부이 등의 SST를 확보한다. 먼저 41.5°C 사례와 공기·바다 온도차를 대조한다. 변수별 편향·MAE·RMSE, 풍향의 원형 각도 오차를 계산하고 관측소와 모델 격자의 대표성 차이를 함께 기록한다.
2. **해무 발생 라벨 확보:** 시정 기준이나 출처가 확인되는 현장 영상으로 지점·시간별 발생/미발생을 정의한다. 해무가 없는 시간도 포함하고 라벨 품질을 관리한다. 날짜·지점을 분리해 임계값 조정과 최종 평가를 나눈다. 발생이 드문 자료에서는 accuracy만 높아질 수 있으므로 precision·recall·F1과 혼동행렬을 함께 본다.
3. **층 높이와 시야를 별도 검증:** 고층 관측·연직 관측·고도별 영상 등으로 해무 상단 오차와 ‘해무 속/위’ 판정 오류를 측정한다. 발생 여부만 맞춘 것으로 층 높이까지 검증됐다고 판단하지 않는다.
4. **예보 리드타임 보존:** 기상 모델 실행 시각·발행 시각·유효 시각·리드타임·해양 제품 식별자를 저장한 뒤 24시간/48시간 앞 성능을 따로 평가한다. 현재 `fetchedAt`은 수집 시각이며 모델 발행 시각이 아니다.
5. **추가 데이터 연동 검토:** KMA AWS/ASOS·해양 관측, GK2A 위성, 적합한 고층 관측은 현재 미연동이다. 관측 가용성·인증·시간 및 공간 정합성을 확인한 뒤 검증 자료로 연결한다.

현재 평가 도구 사용 예시(독립 라벨을 준비한 뒤 실행):

```powershell
npm.cmd run evaluate -- --labels observations.csv --data data/july-2026.json --threshold 65
```
